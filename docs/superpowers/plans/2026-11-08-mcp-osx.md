# mcp-osx Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local stdio MCP server that controls macOS via `osascript`: safe named actions, user-confirmed raw scripts, saved workflows, and app-dictionary discovery.

**Architecture:** A single `runOsa` runner, injected everywhere so tests can mock it. Named actions are data (a script template plus a zod schema) and receive every input through `argv`. A confirmation module picks elicitation or a native JXA `NSAlert`. A workflow store keeps JSON files in `~/.mcp-osx/workflows/`, each with a SHA-256 hash, and the server re-registers `workflow_<name>` tools when the store changes.

**Tech Stack:** TypeScript (ESM, Node 20+), `@modelcontextprotocol/sdk` ^1.32, `zod`, `fast-xml-parser`, `vitest`.

**Spec:** `docs/superpowers/specs/2026-11-08-mcp-osx-design.md`

## Global Constraints

- Node >= 20, macOS only, stdio transport only.
- `osascript` is spawned with `execFile` and no shell. The script goes over stdin (`osascript -l <AppleScript|JavaScript> - ...argv`), and inputs always go through argv, never into script source.
- Confirmation fails closed: an error, timeout, cancel, or missing capability means deny.
- Named actions are non-destructive.
- The native dialog shows the full script and never truncates. Deny is the default button.
- An elicitation accept counts as approval. The threat model is limited to the server's own interface: a plain hash is stored in the workflow file.
- Data dir: `~/.mcp-osx` (override with the `MCP_OSX_HOME` env var). Config: `config.json`. Workflows: `workflows/<name>.json`.
- Default script timeout is 30 000 ms, and the cap is 120 000 ms.

## Review Focus

1. Workflow param values containing quotes, newlines, or AppleScript syntax must arrive as literal argv strings, never executed. Test: `workflows.test.ts › params passed as argv untouched`.
2. A workflow file edited on disk (hash mismatch) must trigger re-confirmation before it runs, and a deny must not run it. Test: `server-tools.test.ts › tampered workflow reconfirms`.
3. A dialog that times out or closes must be treated as deny. Test: `confirm.test.ts › dialog failure denies`.
4. A workflow name such as `../x` or one with spaces must be rejected before any file I/O. Test: `workflows.test.ts › rejects bad names`.
5. An app with no dictionary, or an unknown app name, must return a clear error, not a crash. Test: `dictionary.test.ts › sdef failure gives error`.

### Task 1: Scaffold and osascript runner

**Files:** Create `package.json`, `tsconfig.json`, `.gitignore`, `src/osascript.ts`, `src/errors.ts`, `test/osascript.test.ts`

**Interfaces — Produces:**
- `type Lang = 'applescript' | 'javascript'`
- `type OsaResult = { stdout: string; stderr: string; code: number }`
- `type Runner = (opts: { script: string; lang?: Lang; args?: string[]; timeoutMs?: number }) => Promise<OsaResult>`
- `runOsa: Runner`: never rejects on a non-zero exit; on timeout it returns `code: -1` and `stderr` containing `timed out`.
- `explainError(stderr: string): string`: appends a hint for `-1743` (Privacy & Security › Automation), `-25211` / `-1719` (Accessibility), and `-600` (application isn't running).

  - `error "boom"` gives `code !== 0` and stderr containing `boom`.
  - `delay 5` with `timeoutMs: 200` gives `code -1` and stderr matching `/timed out/`.
  - `explainError('... (-1743)')` contains `Automation`.

### Task 3: Confirmation (elicitation + native dialog)

**Files:** Create `src/confirm.ts`, `src/dialog.ts`, `test/confirm.test.ts`

**Interfaces — Produces:**
- `type ConfirmRequest = { title: string; script: string; lang: Lang; note?: string }`
- `type Elicit = ((message: string) => Promise<'accept' | 'decline' | 'cancel'>) | undefined`
- `nativeDialog(req: ConfirmRequest, runner: Runner, timeoutSec = 120): Promise<boolean>`: JXA `NSAlert` with a scrollable read-only monospaced `NSTextView` showing the full `req.script`. Buttons are `Deny` (default, Return key) and `Allow`. Title and script are passed through argv. The app is activated so the alert comes to the front. Returns true only when stdout is `allow`.
- `confirm(req: ConfirmRequest, deps: { elicit: Elicit; runner: Runner }): Promise<boolean>`: if `elicit` is defined it is used, the message includes the full script in a fenced block, and true is returned only for `'accept'`. If `elicit` throws, fall back to the dialog. If there is no `elicit`, use `nativeDialog`. Any thrown error returns false.

- [ ] Step 1: Tests with a mock runner and mock elicit:
  - elicit `accept` gives true and the runner is not called.
  - elicit `decline` gives false.
  - elicit throws, the runner returns `allow`, and the result is true.
  - No elicit, the runner returns `deny`, and the result is false.
  - `dialog failure denies`: the runner returns `code -1`, giving false. The runner throws, giving false.
  - The script passed to the runner does not contain `req.script`, but `args` does.
- [ ] Steps 2-4: fail, then implement, then pass. Manually smoke-test `nativeDialog` once on macOS. Commit `feat: confirmation`.

### Task 4: Workflow store

**Files:** Create `src/workflows.ts`, `test/workflows.test.ts`

**Interfaces — Produces:**
- `type Param = { name: string; description?: string; required?: boolean }`. Every param is a string, and params map to `argv` in declaration order.
- `type Workflow = { name; description; lang: Lang; script; params: Param[]; approvedHash; createdAt }`
- `hashScript(lang, script): string`: sha256 hex of `` `${lang}\n${script}` ``.
- `validName(name): boolean`: `/^[a-z][a-z0-9_]{0,47}$/`.
- `class WorkflowStore(dir)`: `list(): Promise<Workflow[]>` (skips unparsable files), `get(name)`, `save(w: Omit<Workflow,'approvedHash'|'createdAt'>)`, `delete(name)`, `isApproved(w): boolean`, and `reapprove(name)`, which rewrites the hash. It also exposes `onChange(cb)` and uses `fs.watch` on the directory with a 200 ms debounce.
- `argsFor(w, input: Record<string,string>): string[]`: throws if a required param is missing.

- [ ] Step 1: Tests (temp dir):
  - Save and get round-trip. `isApproved` is true, and editing the file's `script` makes it false.
  - `rejects bad names`: `../x`, `A`, and `has space` throw from `save` and `get`, and no file is created.
  - `params passed as argv untouched`: `argsFor` with value `"; do shell script "rm` returns that exact string.
  - A missing required param throws.
  - `delete` removes the file. `list` ignores `junk.json`.
- [ ] Steps 2-4. Commit `feat: workflow store`.

### Task 5: Dictionary discovery

**Files:** Create `src/dictionary.ts`, `test/dictionary.test.ts`, `test/fixtures/mini.sdef`

**Interfaces — Produces:**
- `listScriptableApps(exec?): Promise<{ name: string; path: string }[]>`: runs `mdfind "kMDItemContentType == com.apple.application-bundle"` restricted with `-onlyin` for `/Applications`, `/System/Applications`, `/System/Library/CoreServices`, and `~/Applications`. It keeps bundles whose `Contents/Info.plist` has `OSAScriptingDefinition` or `NSAppleScriptEnabled` (read with `plutil -convert json -o - `), and excludes paths under `/Library/Caches/` or `/.cache/`. Results are deduped by name (first path wins) and sorted.
- `resolveApp(nameOrPath): Promise<string>`: an absolute `.app` path is used as is. Otherwise the name is looked up with `mdfind kMDItemCFBundleIdentifier`/display name, falling back to `/Applications/<name>.app` and `/System/Applications/<name>.app`. It throws `App not found: <name>` when nothing matches.
- `summarizeSdef(xml: string, filter?: string): string`: compact text with one block per suite and these lines:
  - `cmd <name>(<direct param type>; <param>: <type>[?], ...) -> <result>  — <description>`
  - `class <name> [inherits X]: props <name>: <type> [r], ...; elements <...>`
  - `enum <name>: a|b|c`
  A filter keeps only suites, commands, or classes whose name includes it, case-insensitive.
- `getAppDictionary(app, filter?, exec?)`: `sdef <path>`, summarized and cached in memory by path plus mtime. A non-zero `sdef` exit throws `<app> has no scripting dictionary`.

- [ ] Step 1: Tests:
  - Running `summarizeSdef` on the fixture (Spotify-like: `play track` with a `context` param, a `track` class with `name` r/o, and an enum) gives output containing `cmd play track(`, `class track`, and `name: text [r]`.
  - The filter `track` excludes an unrelated `pause` command.
  - `sdef failure gives error`: a mock exec with exit 1 rejects with `/no scripting dictionary/`.
  - On darwin: `listScriptableApps()` includes `Finder`.
- [ ] Steps 2-4. Commit `feat: dictionary discovery`.

### Task 6: MCP server wiring

**Files:** Create `src/server.ts`, `src/index.ts`, `test/server-tools.test.ts`

**Interfaces — Consumes:** everything above. **Produces:** `createServer(deps: { runner: Runner; store: WorkflowStore; config: () => Promise<Config>; dialog?: typeof nativeDialog }): McpServer`.

Tools:
- Every `Action` becomes a tool. Its result is the stdout text, and an `isError` result carries `explainError(stderr)`.
- `run_applescript{ script, language?: 'applescript'|'javascript', args?: string[], timeoutMs?, saveAs?, description?, params?: Param[] }`:
  1. Confirm. The note says `Will also be saved as workflow "<saveAs>"` when `saveAs` is set.
  2. On deny, return `isError` `Denied by user` and do not run.
  3. Run the script.
  4. When `saveAs` is set and the run succeeded, save it.
  Validate `saveAs` before confirming.
- `list_scriptable_apps`, `get_app_dictionary{ app, filter? }`.
- `list_workflows`, `run_workflow{ name, params?: Record<string,string> }`, `delete_workflow{ name }`. Deleting confirms, with the dialog showing the script being deleted.
- `workflow_<name>` tools: one per workflow, with a zod shape built from its params. Run them through the same function as `run_workflow`. If `!isApproved`, confirm with the note `Script changed on disk since approval`; on allow call `reapprove` and run, and on deny return an error.
- `syncWorkflowTools()`: run at startup and on `store.onChange`. It removes stale `RegisteredTool`s and adds new ones (the SDK emits `tools/list_changed`).
- Elicit adapter: when `server.server.getClientCapabilities()?.elicitation` is set, it calls `server.server.elicitInput({ message, requestedSchema: { type:'object', properties: { approve: { type:'boolean', title:'Run this script?' } }, required:['approve'] } })`. It returns `'accept'` only if `action==='accept' && content.approve===true`.
- `index.ts`: has a shebang, ensures the data dir exists, and connects over `StdioServerTransport`.

- [ ] Step 1: Tests with `InMemoryTransport` and an SDK `Client`, a mock runner, a temp store, and a dialog that returns a preset value:
  - `listTools` includes `set_dark_mode`, `run_applescript`, and `get_app_dictionary`.
  - `run_applescript` denied: the runner is never called and the result is an error.
  - `run_applescript` allowed with `saveAs:'hello'`: the runner is called once, then `listTools` includes `workflow_hello`.
  - Calling `workflow_hello` does not confirm (the dialog mock is not called).
  - `tampered workflow reconfirms`: edit the file's script, and `syncWorkflowTools`/the call triggers the dialog. A deny leaves the runner uncalled.
  - `delete_workflow`: confirm allow, and the tool disappears.
- [ ] Steps 2-4. Commit `feat: mcp server`.
